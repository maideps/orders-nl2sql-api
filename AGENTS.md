# Rules for the AI agent

This project is developed with an AI assistant (Claude Code). These are the rules it
follows in every session. They are a lightweight version of my
[ai-harness-framework](https://github.com/maideps/ai-harness-framework): the same method,
without installing the full harness, because the project is small.

## Workflow

1. **One feature at a time**, in the order of `Features` below. The next one does not
   start until the current one is verified and committed.
2. **Verify before saying "done"**: `python check.py` must pass before every commit. A
   step that did not run is reported as SKIP, never as PASS.
3. **One commit per logical operation**, written by the rule in `Commit messages` below.
4. **Decisions are written down** in `DECISIONS.md`, in the same commit as the code.
5. **AI usage is logged** in `docs/ai-log.md`: what was asked, what was accepted and what
   was corrected.

## Constraints

- NEVER write an API key into the repository. Only `.env` (ignored by git).
- NEVER run SQL generated by the LLM without passing it through the validator.
- Tests never call a real LLM: the client is mocked.
- Do not add dependencies or abstractions the assignment does not ask for.

## Commit messages

The history is read by someone who wants to see how the project was built and why.
Every commit the agent writes follows this rule.

**Before committing**

1. `python check.py` passes. If a layer reports SKIP, the message says so.
2. Review `git status` and `git diff --staged`: only files that belong to this change.
3. Stage one logical operation. Code, its tests and its docs go in the same commit; an
   unrelated fix goes in its own commit.

**Subject line**

- Imperative mood, starts with a capital letter, no final period: "Add", "Fix", "Reject".
- 60 characters or fewer.
- Names the behavior that changed, not the files: "Reject queries that write to the
  database", not "Update validator.py".

**Body**

- Explains why the change exists and which decision or trade-off it carries. The diff
  already shows what changed, so the body does not list files or repeat the code.
- Plain sentences wrapped at 72 characters. No bullet list of edits.
- States limits honestly: what is not covered, not verified or left for later.
- Claims only what was run. Never "tests pass" unless `check.py` ran on this exact tree.
- No references to the chat ("as requested", "per the discussion") and no praise words
  ("robust", "comprehensive", "clean").
- The body can be omitted only when the subject says everything (for example a typo fix).

**Attribution**

- A commit whose content the AI wrote ends with a `Co-Authored-By:` trailer naming the
  model. The author remains the human who reviewed and accepted it.

**Example**

```
Reject queries that read tables outside the allowlist

The LLM can produce valid SELECT statements over tables the API should
not expose, such as sqlite_master. The validator now walks the parsed
query and fails when any table is not in the allowlist. Subqueries and
CTEs are covered; table-valued functions are not checked yet.
```

## Features

| # | Feature | Done when |
|---|---------|-----------|
| 1 | Generate the orders CSV with errors | 1,000+ rows with duplicates, malformed dates and empty amounts |
| 2 | Clean and load into SQLite | Clean data is in the `orders` table and the cleaning has a test |
| 3 | SQL views | `sales_by_month_country` and `top_10_customers` exist |
| 4 | Query validator | Read-only and allowed tables only, with a test |
| 5 | Question endpoint | Question → LLM → validation → result, tested with a mocked LLM |
| 6 | README | How to run it, decisions, next steps and AI usage |
