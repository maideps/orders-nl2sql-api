# Rules for the AI agent

This project is developed with an AI assistant (Claude Code). These are the rules it
follows in every session. They are a lightweight version of my
[ai-harness-framework](https://github.com/maideps/ai-harness-framework): the same method,
without installing the full harness, because the project is small.

## Workflow

1. **One feature at a time**, in the order of `Features` below. The next one does not
   start until the current one is verified and committed.
2. **Verify before saying "done"**: `python check.py` must pass before every commit. A
   step that did not run is reported as SKIP, never as PASS.
3. **One commit per logical operation**, with a message that explains why.
4. **Decisions are written down** in `DECISIONS.md`, in the same commit as the code.
5. **AI usage is logged** in `docs/ai-log.md`: what was asked, what was accepted and what
   was corrected.

## Constraints

- NEVER write an API key into the repository. Only `.env` (ignored by git).
- NEVER run SQL generated by the LLM without passing it through the validator.
- Tests never call a real LLM: the client is mocked.
- Do not add dependencies or abstractions the assignment does not ask for.

## Features

| # | Feature | Done when |
|---|---------|-----------|
| 1 | Generate the orders CSV with errors | 1,000+ rows with duplicates, malformed dates and empty amounts |
| 2 | Clean and load into SQLite | Clean data is in the `orders` table and the cleaning has a test |
| 3 | SQL views | `sales_by_month_country` and `top_10_customers` exist |
| 4 | Query validator | Read-only and allowed tables only, with a test |
| 5 | Question endpoint | Question → LLM → validation → result, tested with a mocked LLM |
| 6 | README | How to run it, decisions, next steps and AI usage |
